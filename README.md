# dsh-workdock

DeepSeek Harness 多目录项目管理插件。一个项目可以关联多个源文件夹，并指定一个主要目录，作为聊天后续操作的工作目录。

当前包版本为 **0.3.1**，开发依赖基于 Harness **0.2.1-rc.5**。插件包含 Host 逻辑和 Web 客户端，需要在提供对应服务的 Harness 环境中运行，不是独立应用。

## v0.3.0 更新亮点

- 新增 AI 回复收藏：保存已完成回复的 Markdown 快照，在项目管理页统一搜索、筛选与查看。
- 支持编辑收藏标题和备注、复制完整回复，以及返回来源会话并定位原回复。
- 收藏在 Host 持久保存，删除原会话或移除项目不删除快照；不自动加入模型上下文。
- 从旧版升级后请完整重启 Harness，同时加载新的 Host 接口和客户端代码，仅刷新页面不足以完成更新。

## 功能概览

- **多目录项目**：添加、编辑项目名称和源文件夹，设置唯一主要目录。
- **聊天关联**：保存项目时关联当前聊天，也可从项目列表新建会话；不再提供单独的“用于当前聊天”操作。
- **原生侧栏集成**：保存后同步工作区；支持项目行右键菜单和“…”菜单。
- **快捷添加**：点击工作区标题旁原有的“添加工作区”按钮，直接打开空白“添加项目”表单。
- **主要目录提示**：已管理项目的侧栏悬浮提示显示当前主要目录，而非原始工作区路径。
- **持久化与冲突检测**：项目和聊天绑定通过 Harness Storage Domain 保存，编辑时检查版本冲突。
- **项目整理**：项目管理列表支持置顶和取消置顶；侧栏原生整理功能通过“更多”入口访问。
- **颜色标记**：项目和会话可分别设置红、橙、黄、绿、蓝、紫六种预设颜色，或通过取色器 / HEX 色值自定义，支持清除；配置持久保存，不改变聊天状态或工作目录。
- **打开文件夹**：从项目行菜单调用 Host 所在系统的文件管理器。
- **聊天右键交给宿主**：插件不再接管聊天正文文件引用的右键，宿主自带的文件操作保持原样。
- **收藏回复**：星标保存已完成的 AI 回复，在项目管理页搜索、按项目筛选、编辑备注并跳转原对话。
- **隐藏对话轮次**：每轮底部操作栏的时间前提供“隐藏本轮”图标，隐藏后仅留紧凑单行恢复入口；支持恢复当前会话的全部隐藏轮次，仅影响当前浏览器正文显示。
- **独立管理页**：在 Harness 主区域管理项目，从侧栏进入；支持每页 10 / 25 / 50 / 100 项。
- **快速查找**：按项目名、主要目录和所有源目录搜索，支持名称、最近使用排序；置顶项目始终优先。
- **安全编辑**：未保存修改关闭前确认，支持 Ctrl/Cmd+Enter 保存、目录自动命名、同名目录区分和移除目录后短暂撤销。
- **目录维护**：显示不可用目录，支持复制主要目录路径。
- **无聊天浏览**：没有活动聊天时也可打开项目列表、搜索、打开文件夹或新建项目聊天。

## 安装与更新

通过 Harness 的 `plugin_manager` 安装本地 bundle。将下面的路径替换为实际项目根目录，该目录需包含 `package.json` 和 `cordis.patch.yml`：

```json
{"action":"install_bundle","target":"C:\\path\\to\\dsh-workdock"}
```

也可以在 Harness 聊天中请求模型使用上述参数安装。检查工具返回的 `application` 和 `warnings`，按提示启用插件或重启 Harness。更新本地 JavaScript 后建议完整重启，以重新加载 Host 和客户端代码。

仓库包含已构建的 Host 发布入口 `index.js`，直接安装现有源码目录不需要先安装开发依赖。修改 Host 源码后需要重新构建，再更新或重新加载插件。

Host 依赖 `storageDomain`、`commands`、`tools`、`systemPrompt`、`workspaceRegistry`、`connection` 和 `agents` 服务；客户端依赖标准侧栏、布局、聊天、工作区、会话控制及目录选择器组件。其他 Harness 版本的兼容性需另行验证。

## 使用

### 添加项目

1. 先打开或创建一个聊天。
2. 点击左侧“工作区”标题旁原有的添加按钮，直接进入“添加项目”。也可以从侧栏打开项目管理页后选择“添加项目”；聊天尚未关联项目时，输入框下方的项目按钮也可直接添加。
3. 输入项目名称，点击“添加文件夹”，通过目录选择器添加一个或多个源文件夹。名称未手动编辑且仍为空时，第一个目录会自动建议项目名。界面不提供手动输入路径入口。
4. 第一个添加的目录自动成为主要目录。如需切换，在其他目录行悬停或键盘聚焦后，点击“设为主要目录”；触屏设备始终显示该按钮。点击文件夹名称不会切换主要目录。
5. 点击“保存”。配置会绑定当前聊天，并尝试同步到左侧原生工作区树。

项目名称不能为空，至少保留一个源文件夹，主要目录必须属于源文件夹列表。移除主要目录后，必须重新指定一个才能保存。保存时会校验目录是否存在、是否为目录，并规范化和去重路径；不同项目不能使用同一个主要目录。

保存成功会关闭添加/编辑表单；从管理页进入的表单会返回原列表，并保留搜索、排序和页码。从工作区菜单直接打开的表单则直接关闭。保存失败时保留表单并显示错误，便于重试。取消、关闭、Esc 或点击遮罩时，若有未保存修改会先确认放弃。支持 Ctrl/Cmd+Enter 保存，编辑时自动聚焦项目名称。移除源目录后可在短暂撤销入口有效期间恢复；保存前不会修改磁盘文件。

> 工作区标题工具栏顺序为：搜索 → 视图设置 → 项目管理 → 添加项目。宿主已有添加按钮时保留其原有图标和提示文字，点击打开添加项目表单；缺少原生添加按钮时由插件补充末尾按钮，不重复显示。插件同时解除原生工具栏仅容纳两个图标的 60px 宽度限制，防止末尾添加按钮被裁切；展开搜索时仍沿用宿主的收起规则。当前兼容中文“添加工作区”和英文“Add workspace”按钮标识。添加及编辑保存仍需就绪的聊天；没有活动聊天时可通过“项目管理”图标浏览已有项目。

### 管理与切换项目

点击侧栏“工作区”标题右侧工具栏中的文件夹列表图标（悬浮提示“项目管理”），在 Harness 主区域打开独立管理页，点击“返回聊天”可回到会话。原侧栏独立“项目管理”文字入口已移除。聊天输入框下方的项目入口使用 24px 图层图标，不显示项目名以节省空间；悬停显示项目名与主要目录，并保留无障碍名称。点击时重新读取当前会话的项目关联，打开对应编辑框，不进入管理列表；仅在成功确认未关联项目时打开添加表单。读取失败会提示重试，不会误入添加表单；切换会话后丢弃旧请求的弹窗结果。编辑框通过全局浮层在窗口中央显示，不受底部输入区的定位或变换影响。保存或取消后仍停留在聊天。

列表提供以下操作：

| 操作 | 行为 |
| --- | --- |
| 编辑项目 | 修改名称、源文件夹和主要目录；保存时也会绑定当前聊天 |
| 置顶 / 取消置顶 | 修改项目列表中的置顶状态 |
| 新建会话 | 使用项目主要目录创建或取得工作区，等待全新会话创建成功后返回并打开会话；失败保留管理页并显示错误 |
| 刷新 | 重新读取项目，并重试与原生工作区树的同步 |
| 搜索 | 按项目名称、主要目录和所有源目录过滤，不区分大小写 |
| 分页 | 每页 10 / 25 / 50 / 100 项，记住当前浏览器的选择；搜索和排序从第一页开始 |
| 排序 | 名称或最近使用；置顶优先，记住当前浏览器的选择 |
| 复制路径 / 打开文件夹 | 复制主要目录，或在 Host 所在机器打开目录 |

项目列表中的置顶是本插件的配置，不等同于原生侧栏的置顶设置。

在管理页添加、编辑或取消表单后保留搜索、排序和页码；删除后若当前页已空则自动回到有效页。保存以及从列表新建会话会更新最近使用时间；旧项目在首次使用前按未使用处理。没有活动聊天时仍可查看、搜索、整理项目、打开文件夹或新建会话；添加和编辑需先打开聊天。

右下角的操作提示（应用项目、复制路径等成功反馈）在 **3 秒后自动关闭**；错误提示与侧边栏同步警告不会自动消失，需要手动关闭或重试同步。

项目列表会提示不可用的目录；编辑时会自动检查目录状态，不可用的目录需移除后重新添加。同名源文件夹会增加父目录信息以便区分，完整路径仍可通过悬浮提示查看。复制路径依赖浏览器剪贴板权限，失败时显示错误，不会假装复制成功。

### 收藏回复

- 在已生成完成的 AI 回复操作栏点击星标收藏，再次点击取消。只保存该条回复的原始 Markdown 文本，不保存推理过程、工具日志或附件文件。无文本回复不提供收藏；生成中的回复不能收藏。
- 打开 **项目管理 → 收藏回复** 查找，不新增侧边栏入口。默认筛选当前聊天关联项目，可切换全部项目、未关联项目或其他项目。按收藏时间倒序，搜索正文、标题、备注和来源会话名称；命中正文时显示附近摘要。
- 收藏标题默认取关联问题的首行（没有问题时取回复首行），支持修改标题和备注、复制完整回复、取消收藏。未保存标题或备注时切换条目、页签或返回聊天会确认；其他窗口已修改的收藏需要重新读取，防止覆盖。
- 点击“回到原对话”会先读取来源会话及历史页，再恢复该轮的本地隐藏状态、定位并短暂高亮。来源不存在或不可访问时明确提示，不删除快照。
- 快照和来源引用保存在 Host 的 Storage Domain 中，刷新、重启后仍保留，不依赖浏览器 `localStorage`。同一会话同一回复重复收藏不会增加记录；重新生成或编辑原回复不会静默覆盖已有快照。删除原会话或移除项目不会删除收藏。
- 收藏使用现有 `/api/dsh-workdock` 认证且仅所有者可用的接口，不添加模型工具，不将快照带入项目列表或模型上下文。单条回复文本上限为 1 MiB（UTF-8），备注上限 32768 字符。
- 客户端通过宿主 `conversation.chat.assistant-actions` 插槽以及 Conversation 的 `chat` 视图快照读取已完成回复，详情使用宿主 Markdown 组件。依赖当前 Harness 的该公开接口形状；升级宿主需回归验证。旧版插件需更新后完整重启以加载新 Host 接口和客户端，不能只刷新页面。

### 隐藏与恢复单轮对话

- 点击每轮底部操作栏、时间前的“隐藏本轮”图标（划线眼睛），折叠该轮的提问、回复及工具过程。图标保留悬停提示和无障碍名称，不再单独占一行。原位置仅保留约 22px 高的“本轮对话已隐藏 / 恢复显示”紧凑单行，不显示虚线框或额外上下留白；点击“恢复显示”即可展开。
- 有隐藏记录时，最底部状态栏的项目标签后显示“恢复全部”眼睛图标，不再占用输入框上方空间。悬停提示和无障碍名称为“恢复全部隐藏轮次 (N)”；点击只恢复当前会话，包括暂未加载到正文中的轮次。
- 隐藏偏好以会话 ID + 轮次编号保存在当前站点的浏览器 `localStorage`，不保存消息正文。刷新后仍保留，同站点标签页同步；不跨浏览器或设备同步，清除站点存储会恢复显示。
- **这不是删除或隐私擦除**：不修改历史事件、工具记录、摘要或模型上下文，不减少 token 用量；原始内容仍在日志和 DOM 中，搜索、导出及其他视图仍可能显示它。隐藏正在运行的轮次不会停止模型或工具。
- 本地存储不可写时显示错误，不会假装保存成功。卸载插件会恢复正文显示，但保留浏览器偏好以便再次启用。
- 集成使用宿主 `conversation.chat.turnTail` / `conversation.composer.dock` 插槽及 `data-chat-turn` / `data-chat-flow-key` 正文语义标记，不修改宿主源码。时间前没有公开插槽，因此用 React portal 将插件自有图标容器放在本轮 `[data-clock="end"]` 的 `_endInfo` / `_timeEnd` 结构内；不搬动或修改原生按钮、用量入口或时间节点。操作栏尚未出现或结构不匹配时暂不显示隐藏图标，重绘后自动重试。测试覆盖与当前安装版相同的 NodeSeat / ChatGroupSeat 结构；宿主变更这些标记或插槽后需重新验证兼容性。
- 更新插件后需重新加载客户端代码（通常完整重启 Harness）；没有运行同一 checkout 的 Web 开发构建 watcher 时，不保证保存源码后当前页面自动生效。

### 项目与会话颜色标记

- 点击侧栏项目行或会话行末尾的圆点，选择颜色；前面的项目名称或会话标题同步变色，项目管理列表中的名称也使用相同颜色。空心圆表示未标记，选择“无颜色”可清除，并恢复原生文字颜色；时间、状态图标和操作按钮不受影响。
- 项目也可从项目行右键 / “…”菜单中的“颜色标记”，或项目管理列表的同名按钮进入。
- 项目和会话颜色互相独立，不自动继承；同一项目在管理列表和侧栏显示相同颜色。无需打开聊天即可修改颜色，重启后仍保留。
- 菜单底部的“自定义颜色”支持取色器和 `#RRGGBB` 格式的 HEX 输入（如 `#FF8800`），点击“应用”或在色值框中按 Enter 保存；输入无效时不能应用，Esc 取消未保存的颜色。重新打开会显示已保存色值。自定义颜色同样用于圆点和标题。
- 颜色菜单支持方向键、Home / End、Tab 和 Esc；色值输入框保留原生光标操作，Tab 可访问取色器、色值框及“应用”按钮；会话原有右键菜单和运行状态图标保持不变。
- 后台接口支持 `{ "action": "set_color", "target": "project|workspace|session", "id": "实际ID", "color": "red|orange|yellow|green|blue|purple" }`，`color` 也接受六位 HEX 字符串（如 `"#FF8800"`，保存为小写），清除时传 `color: null`。不接受简写 HEX、透明色或任意 CSS 表达式。颜色只影响显示，不修改项目版本和聊天绑定。
- 升级到支持自定义颜色的版本后需完整重启 Harness，重新加载后台颜色校验及存储规则，仅刷新页面不足以更新后台。

### 左侧项目行菜单

在原生工作区名称上右键、点击项目行“…”或聚焦后按菜单键 / `Shift+F10`，均打开同一套插件菜单，条目、顺序和样式一致，仅弹出位置跟随触发点。会话子行保留宿主自己的右键行为。

- **编辑项目**：打开所选项目的目录设置。尚未纳入管理的原生工作区会预填其名称和目录，保存后成为插件项目。主要目录在编辑窗口内通过目录行上的“设为主要目录”切换。
- **在资源管理器中打开**：打开已管理项目的主要目录；未配置项目时打开原生工作区目录。
- **新建会话**：在所选原生工作区中新建会话；已管理项目在后续执行时应用主要目录。
- **置顶 / 取消置顶**：直接将原生项目树中的项目排到前面，不增加额外区域或重复项目；最近置顶的排在最前。通过宿主工作区排序接口移动整个项目及其会话，保留原生展开、滚动及键盘行为。取消置顶时按置顶前记录的位置恢复，其他普通项目保持当前相对顺序。
- **更多…**：转到宿主原生项目行菜单。
- **移除本地项目**：确认后移除项目配置及所选侧栏工作区注册，不删除磁盘文件和聊天记录。

左侧树置顶按原生工作区 ID 保存在当前浏览器的本地存储，刷新、重启后保留，同源标签页同步；旧版的置顶记录自动用于原树排序。不要求先保存为插件项目，也不会创建聊天或修改聊天绑定。排序本身写入宿主的工作区顺序，其他客户端也可能看到这个顺序；置顶偏好与管理页列表置顶分别保存，不修改宿主会话置顶。新工作区自动排在置顶项目之后，已删除的 ID 会被忽略。需要宿主提供 `workspaces.insertBefore`；不支持或排序失败会显示错误，不会改用额外置顶区。卸载只停止维持置顶，不重置已保存的宿主顺序。

菜单支持方向键、`Home`、`End`、`Tab`、`Escape` 和点击外部关闭。编辑会使用当前属于该工作区的聊天，否则创建并打开该工作区的空白聊天；仅打开菜单不会创建聊天。打开文件夹、复制路径和移除配置不再为了管理操作创建空白聊天。

侧栏兼容层依赖宿主的 `data-row-key="workspace:<id>"` 以及工作区服务中的有效 ID。没有对应标识的第三方项目树不会被拦截。工作区标题栏图标使用宿主 WorkspaceBrowser 的 CSS 模块结构定位并继承原生按钮样式；搜索展开时随原生工具栏隐藏，宿主重绘后自动恢复，不接管搜索、视图或添加按钮。该位置目前没有公开扩展槽，宿主结构变化可能需要更新兼容层。插件卸载时清理图标、观察器和事件监听，并恢复被隐藏的原生悬浮卡片。

### 移除配置与删除工作区

- 从聊天输入框下方的项目列表进入编辑，再点击“移除本地项目”：只移除插件项目配置及其聊天绑定，不主动删除原生工作区注册。
- 从侧栏项目行进入设置后移除，或直接使用项目行菜单的移除/删除操作：还会删除所选原生工作区注册。
- 两种方式都不删除磁盘文件。移除项目配置会保留会话专属目录；没有专属目录的会话退回会话初始目录。当前就绪会话立即同步，其他会话在下一次操作时同步。

## 会话工作目录

底部项目标签与恢复隐藏轮次图标之间新增 **文件夹图标**，点击设置当前会话工作目录；悬停显示生效路径及来源。设置专属目录后图标高亮，无需在底部增加路径文字。会话右键菜单也提供“设置工作目录…”，使用 Harness 官方 `contextMenus` 扩展，保留重命名、分叉和归档等原生操作。打开其他会话的设置会先打开该聊天；尚未就绪时，等待就绪后点击“重新读取目录”。

设置弹窗提供：

- **跟随项目目录**（默认）：采用项目当前主要目录，无项目时采用会话初始目录。
- **会话专属目录**：从项目源目录中选择，或使用目录选择器选择 Host 上其他目录。路径需存在且为目录。
- **恢复跟随项目**：清除专属路径并立即应用跟随结果，保留显式跟随状态，子会话不会因此重新继承父目录。

有效目录统一按 **会话专属目录 → 项目主要目录 → 会话初始目录** 解析，保存在 Host 插件存储中，而不是浏览器本地偏好；刷新或重启后保留。不同会话独立，项目主要目录及侧栏归属不变。项目主要目录变化不会覆盖专属目录；关联到其他项目或保存新项目时，必须明确选择“保留会话专属目录”或“恢复跟随项目”。版本检查防止覆盖其他窗口的目录修改，冲突后重新读取再保存。

新建项目会话默认跟随项目。子会话在创建时独立保存核心已解析的工作目录，通常继承父会话当时的有效目录，也尊重调用者显式指定的子会话目录；后续父子设置互不覆盖。插件启用前已存在且没有目录记录的子会话无法追溯历史，只能冻结首次观察到的当前目录，接口会返回 `inheritanceWarnings`。

**安全边界**：界面配置修改使用 Agent 的维护锁；会话正在执行任务时明确提示完成后重试，不中断任务、不在执行中切换目录。目录失效时显示原路径和错误，可通过弹窗改选或恢复跟随，不会静默切换到其他目录。目录选择不自动扩大沙箱的可写根目录，也不授予访问权限；项目以外目录可能仍需 Harness 的单独授权。

## 主要目录的作用与边界

插件通过 Harness 的 `workingDirectory.set(agent, path)` 设置会话工作目录，不使用全局 `process.chdir()`。保存或绑定时应用统一解析的有效目录；构造模型请求和执行工具前也会重新校验、同步。模型收到的工作目录说明与工具使用同一解析规则，不再要求有专属目录的会话强制回到项目主要目录。

- 内置文件工具的相对路径和新启动命令使用会话有效目录。
- 其他项目源文件夹写入上下文作为只读参考；被选为有效目录的源文件夹不再同时列为只读参考。
- 切换主要目录时保留历史目录关联和原生工作区身份，不迁移或重写聊天历史。
- 没有显式绑定时，插件可按聊天初始目录识别唯一匹配的项目；多个项目存在历史匹配时，需要显式绑定。子会话可继承父会话的项目绑定。
- 已保存项目在插件启动时自动尝试同步到原生工作区树，读取列表时也会重试。同步优先复用主要目录或历史目录对应的工作区，并同步项目名称。

**这不是文件系统沙箱，也不提供强制只读权限。** 任意 Shell 命令、绝对路径及第三方工具的访问权限，仍由 Harness 的权限与沙箱策略决定。其他源目录不会因为加入项目而自动获得额外权限。

已经运行的终端、持久 Shell 会话和后台进程保留各自的工作目录，不会随设置迁移；需要时关闭后重新启动。配置界面仅在会话空闲时保存，变更用于后续执行。有效目录失效时插件会报错，不会静默改用其他目录。工作目录事件与插件存储并非跨服务原子事务：应用目录后才保存配置，保存失败会尝试回滚目录；回滚失败会明确报错，持久配置不变，下一次目录同步会按持久配置修复。

文件管理器运行在 **Host 所在机器**：Windows 使用 `explorer.exe`，macOS 使用 `open`，其他平台使用 `xdg-open`。路径作为独立参数传递，不经过 Shell；启动失败时在界面显示错误。

## 命令与模型工具

界面通过 `POST /api/dsh-workdock` 后台接口读写，不调用斜杠命令，也不会生成 `projects · {...}` 命令聊天记录。该接口使用 Harness Connection 的认证和仅所有者可调用的路由机制。保存配置、绑定以及读取/设置会话目录需要就绪的聊天；读取列表、检查目录、记录最近使用、打开文件夹、置顶和移除配置允许不提供聊天 ID。只要提供 `sessionId`，必须匹配已就绪的 Agent；不会忽略无效会话而修改其他会话。`open_folder` 可通过 `workspaceId` 或项目 `id` 指定目录；`check_directories` 接收 `folders`，返回逐路径的 `directoryWarnings`；`touch` 接收项目 `id`，只更新最近使用时间。

手动输入 `/projects` 可查看项目；附带 JSON 可执行操作，例如：

```text
/projects
/projects {"action":"save","title":"示例项目","folders":["C:/work/app","C:/work/reference"],"primary":"C:/work/app"}
/projects {"action":"bind","id":"实际项目ID"}
```

路径需替换为 Host 上真实存在的绝对目录。模型工具名为 `project_manager`，支持同一套核心操作：

| action | 主要参数 |
| --- | --- |
| `list` | 无 |
| `save` | `title`、`folders`、`primary`；更新已有项目还需 `id` 和当前 `revision` |
| `bind` | `id` |
| `remove` | `id` |
| `pin` | `id`，切换置顶状态 |
| `get_session_directory` | 无；返回 `sessionDirectory` 的路径、来源及 `revision` |
| `set_session_directory` | `path`（绝对目录或 `null`）及刚读取的 `directoryRevision` |

`set_session_directory` 的 `path: null` 表示显式跟随项目。`save` / `bind` 若切换项目且当前有专属目录，还需 `directoryPolicy: "keep"` 或 `"follow"` 及匹配的 `directoryRevision`；编辑同一个项目不会重置专属目录。目录失效时只读接口仍返回原选中路径及 `sessionDirectory.validationError`，便于修复，执行接口则严格拒绝失效目录。

手动命令和模型工具调用仍产生 Harness 正常的可见结果。`remove` 只删除插件配置和绑定，不删除原生工作区注册或磁盘文件。

### 聊天文件右键

插件不再接管聊天正文文件引用的右键。聊天区域（包括 Markdown 文件链接、`@` 提及、代码块和输入框）的右键始终由宿主处理：宿主已自带文件相关操作，插件不再提供重复菜单。

该能力已从代码中移除，而不是用开关隐藏：`client.js` 不含受影响的监听器、浮层与文案，`src/index.js` 不再接受 `open_file` / `reveal_file`，`folder-opener.js` 只保留项目行“打开文件夹”所需的目录打开能力。旧版菜单依赖宿主内部样式类名（`_fileLink_`）和 `title` 路径，升级后本就不稳定，因此不再维护。

## 常见问题

- **提示先打开聊天或聊天尚未就绪**：打开或创建聊天，待会话就绪后重试。
- **保存按钮不可用**：检查名称、源文件夹和主要目录是否完整；主要目录必须属于源文件夹之一，删除后需改选其他目录。
- **项目已在其他窗口更新**：取消当前编辑，刷新列表，再打开最新配置修改，避免覆盖他人的更改。
- **配置已保存，但侧栏同步失败**：保存操作仍视为成功并关闭表单，警告单独显示。检查目录可用性，点击警告中的重试同步或项目管理中的“刷新”，不必重复保存或添加项目。
- **切换后旧终端仍使用原目录**：已运行进程不会迁移，重新启动进程。
- **目录不可用**：查看具体路径并移除该目录后重新添加；不会静默切换到其他目录。
- **侧栏按钮或菜单没有被接管**：确认插件客户端已加载；宿主版本、语言标识或第三方侧栏结构变更可能影响兼容层。

## 开发与验证

使用支持 Node.js 24 构建目标的开发环境，在项目根目录执行：

```powershell
npm ci
npm run build
npm run check
npm test
```

分发前可打包到 `dist`：

```powershell
npm pack --pack-destination dist --ignore-scripts
```

先运行构建可确保 `dist` 目录存在，并更新 Host 发布入口及依赖许可说明。打包名称由 `package.json` 中的版本决定。

| 文件 | 用途 |
| --- | --- |
| `client.js` | React 客户端、项目表单、侧栏事件兼容层和浮层 |
| `src/index.js` | Host 服务注册、后台接口、命令、工具和工作目录同步 |
| `core.js` | 项目存储、路径验证、绑定、版本冲突检查和上下文 |
| `folder-opener.js` | 系统文件管理器启动 |
| `index.js` | 构建生成的 Host 发布入口，不要手动修改 |
| `scripts/build.mjs` | 打包 Host 依赖、检查外部引用并生成许可说明 |
| `cordis.patch.yml` | Harness bundle 插件注册配置 |
| `test/` | 核心逻辑、后台接口、客户端交互及独立加载测试 |

修改 `src/index.js`、`core.js` 或 Host 依赖后，运行 `npm run build` 更新根目录 `index.js`。客户端作为独立入口发布，修改 `client.js` 后需重新加载客户端。

测试覆盖多目录与主要目录切换、持久恢复、并发编辑、删除绑定、文件系统校验、最近使用、无聊天管理、部分同步失败、原生工作区同步、后台接口、文件管理器参数，以及 React + jsdom 菜单和表单交互。隐藏轮次测试还覆盖整轮工具记录、单个/全部恢复、焦点回退、分页与流式节点、多窗格隔离、跨标签页存储和写入失败。独立加载测试验证发布入口在没有项目 `node_modules` 的目录中仍可导入并注册服务。

若受限沙箱禁止 Node 测试运行器创建子进程，可使用 `node --test --test-isolation=none test/*.test.js` 在同一进程运行这些测试。

可运行 `node scripts/preview-project-page.mjs --verify`，用已安装的 Chrome 加载真实客户端与 React，仅替换 Harness 服务及接口边界，校验 67 项数据的分页、搜索、编辑返回、移除提示字号和撤销。默认使用 Windows Chrome 安装路径，可通过 `CHROME_PATH` 指定浏览器；结果、预览和截图输出到 `dist`。仅生成预览可省略 `--verify`。

隐藏轮次布局另有 `node scripts/preview-hidden-turns.mjs --verify` 离线预览：加载真实插件、React 和已安装 Harness 的操作栏样式，检查图标紧邻时间、工具栏重绘、隐藏/恢复、四轮紧凑高度及窄屏布局。使用 `DSH_APP_ASAR` 可指定安装归档，`CHROME_PATH` 指定浏览器；预览和截图写入 `dist`，需要目录可写及浏览器启动权限。

部分 Harness 集成测试依赖本地 `.reference/runtime/` 真实 API 夹具；缺少时自动跳过，该目录不随包分发。自动化交互测试与离线浏览器预览不等同于运行中 Harness UI 的实机验收。
