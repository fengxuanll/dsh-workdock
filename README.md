# dsh-workdock

DeepSeek Harness 多目录项目管理插件。适配并核对本机 DeepSeek Harness Desktop **0.2.1-rc.5** 的 Cordis 插件接口。

## 功能

- 项目列表、重命名、置顶和分区。
- 一个项目关联多个源目录，通过单选按钮设置唯一主要目录。
- 文件夹选择器和手动输入绝对路径；保存时校验目录、消除重复路径。
- 点击“用于当前聊天”绑定项目；编辑主要目录后，关联聊天后续工作跟随设置。
- “新建聊天”使用主要目录创建原生 Workspace 聊天；保留原有聊天侧栏。
- 项目及绑定通过 Harness Storage Domain 持久保存；并发编辑会检测版本冲突。
- 移除项目只移除配置，不会删除磁盘文件。
- 左侧项目树支持右键管理，也支持键盘菜单键 / Shift+F10。

## 安装

这是 **DeepSeek Harness** 插件包，需要在 Harness 中安装。

在 DeepSeek Harness 聊天中发送：

```text
请使用 plugin_manager 安装本地 bundle：E:\Prog\dsh-workdock
action 为 install_bundle，target 为上述完整目录。
```

对应工具参数：

```json
{"action":"install_bundle","target":"E:\\Prog\\dsh-workdock"}
```

安装后检查工具返回的 `application` 和 `warnings`。如提示需要重启，重启 Harness。更新已安装的 JavaScript 后也应重启。插件需要当前 profile 提供 storageDomain、commands、tools、systemPrompt 服务，以及常规 Web/桌面界面组件。

可分发包位于 `dist/dsh-workdock-0.1.8.tgz`。本地安装优先使用上面的源码目录。

### 0.1.8 交互细节

未选中的源文件夹行在悬停或键盘聚焦时显示“设为主要目录”按钮，点击按钮切换；当前主要目录保留标记。点击文件夹名称不再直接改变主要目录。触屏设备始终显示设置按钮。添加目录只通过选择器进行，移除了手动输入路径入口。

项目行菜单缩小了行高、宽度和分隔线间距。已管理项目的原生目录悬浮卡片会被抑制：除拦截原生 HoverCard 外层的进入事件，也处理已延迟挂载的原生卡片。匹配基于原生卡片标记、工作区路径及项目标题；不会隐藏其他聊天或工具的卡片，插件卸载时恢复原生样式。

### 0.1.7 后台通信

项目管理界面的读取、刷新、保存、绑定和打开文件夹改走 `/api/dsh-workdock` 后台接口，不再通过 `/projects` 命令通信，因此不会再生成 `projects · {...}` 聊天记录。错误仍显示在管理窗口或菜单内。接口使用 Harness Connection 的认证及仅所有者可调用的 exact Fetch route，保留桌面转发和反向代理路径前缀。旧版已经写入聊天的历史记录保留。

手动输入 `/projects` 和模型主动调用 `project_manager` 时仍使用 Harness 的正常可见记录；后台界面操作不会调用它们。

### 0.1.6 界面与目录提示

编辑项目采用紧凑的 Codex 风格布局：带文件夹图标的项目名称输入框、圆角源文件夹列表、每行右侧的移除按钮，以及列表底部的“添加文件夹”。主要目录通过目录行的“设为主要目录”按钮切换，选中行显示标记。完整路径通过悬浮提示查看。

已管理项目的原生悬浮卡片改为显示插件保存的主要目录。保存设置后提示立即更新。原生 Workspace 的初始路径仍保留用于聊天归属，其身份和历史不变，插件不直接修改 Harness 内部持久记录。未纳入项目管理的工作区沿用宿主提示。

### 0.1.5 新功能

项目行“…”按钮菜单新增“项目管理”和“在资源管理器中打开”，保留重命名、删除及更多入口。项目管理直接打开所选项目的多目录设置；打开文件夹使用该项目的主要目录，未配置项目时使用原生工作区目录。右键菜单也提供打开文件夹入口。文件管理器由 Host 启动，路径按独立参数传递，不经过 Shell；启动失败会在菜单中显示错误。

### 0.1.4 修复

项目保存后会通过 Host 的 `workspaceRegistry` 注册到原生左侧项目树，不再需要先点“新建聊天”。启动插件时自动补齐旧版本已经保存的项目；项目管理中的“刷新”也会重试同步。同步按目录复用已有工作区，避免重复创建；改名同步到树中，切换主要目录时保留已有工作区和聊天归属。目录不可用等同步失败会显示在管理窗口中，修复目录后可刷新重试。

### 0.1.3 修复

补齐客户端 `remote.commands` 与 `remote.directoryPicker` 的独立服务注入声明，修复右键编辑时 `cannot get property "remote.commands" without inject` 的报错。交互测试增加了嵌套服务的注入检查，并覆盖目录选择器调用。

### 左侧项目树右键管理（0.1.2）

在左侧项目树的项目文件夹行上右键，菜单提供：

- **编辑项目 / 设置主要目录**：直接打开对应项目的多目录编辑窗口。尚未配置的原生项目会以其当前目录预填，保存后纳入项目管理。编辑名称后会同步左侧项目标题。
- **用于当前聊天**：将所选项目的主要目录应用到当前聊天。
- **新建聊天**：使用所选项目对应的原生工作区新建聊天；配置过主要目录的项目会在后续执行前应用主要目录。
- **置顶 / 分区 / 更多…**：打开原生项目行的更多菜单，复用宿主及已安装侧栏插件的置顶、分区等功能。
- **移除本地项目**：确认后移除左侧工作区注册和本插件中的目录配置，保留磁盘文件及聊天记录。

菜单支持方向键、Home/End、Tab、Escape 和点击外部关闭。会话子行保留自己的右键行为。未打开该项目聊天时，点击编辑会创建并打开一个该工作区的空白聊天，以便应用会话主要目录；仅打开右键菜单不会创建聊天。

原生版本没有项目菜单扩展插槽，因此兼容层仅识别 `data-row-key="workspace:<id>"`，并用 workspaces 服务核对 ID；菜单和编辑窗口通过 `shell.overlay` 插槽渲染。没有匹配 ID 的第三方项目树不会被拦截。监听器会在插件卸载时清理。

### 从 0.1.0 更新

0.1.0 在软链接本地安装时可能报 `Cannot find package '@deepseek-ai/dsh-storage-domain'`。0.1.1 已将 Host 所需依赖编译进 `index.js`，运行时无需从 Harness 安装目录或源码父目录查找依赖。

如果当前安装是 `link:E:/Prog/dsh-workdock`，源码目录已包含修复后的入口：完整退出并重新打开 Harness，再启用项目管理插件即可。如果使用的是旧安装包，改用 0.1.1 安装包重新安装后重启。

## 使用

1. 打开一个聊天，点击输入框下方的项目按钮。左下角不再提供“项目管理”入口；项目行“…”菜单及右键编辑入口保留。
2. 点击“添加项目”，输入名称，添加一个或多个源文件夹。
3. 在目标目录行悬停，点击“设为主要目录”，再点击“保存”，会立即绑定当前聊天并应用主要目录。删除当前主要目录后，必须重新选择主要目录才能保存。
4. 在项目间切换时点击“用于当前聊天”，或“新建聊天”。输入框下方会显示当前项目名称。
   - 保存项目成功或编辑时点击“取消”均直接关闭整个窗口，不再返回项目管理列表；取消不保存更改，保存失败时保留编辑内容和错误提示，方便重试。
5. 后续可通过“编辑项目”修改主要目录。已有聊天保留原始身份和历史记录，后续执行切换到新的主要目录。

项目管理界面通过后台 Fetch API 读写。保存和绑定项目需要就绪的聊天，以便应用主要目录；读取接口也支持无聊天的请求。也可以手动使用 `/projects` 查看项目；模型可以使用 `project_manager` 工具执行同一套操作。

## 主要目录的具体行为

插件调用官方 `workingDirectory.set(agent, path)`，不会执行全局 `process.chdir()`。因此不同聊天可以使用不同项目，互不切换宿主进程目录。每次构造模型请求、执行工具前，插件重新校验并同步主要目录。目录不存在时操作报错，避免静默写入其他目录。

内置文件工具的相对路径及新启动的命令使用会话主要目录。提示上下文同时提供其他源目录，并要求将它们仅作为读取参考。主要目录变更后，旧主要目录发起的聊天仍能识别所属项目。存在多个历史匹配时，需要显式点击“用于当前聊天”。

**这是工作目录管理功能，不是文件系统沙箱。** 模型提示要求只在主要目录修改，但任意 Shell 命令、绝对路径和第三方工具的写入权限仍由 Harness 自身的权限和沙箱策略决定。已经运行的终端、持久 PowerShell 会话和后台进程不会被迁移，切换后应关闭旧进程并重新启动。进行中的工具调用不会被中断；变更用于后续执行。

移除项目后，聊天保留最后一次工作目录，不会自动返回之前的目录。其他源目录不会因此自动获得额外的读写权限。

## 验证

```powershell
npm ci --ignore-scripts
npm run build
npm run check
npm test
npm pack --pack-destination dist --ignore-scripts
```

已提交编译后的入口，用户安装插件无需构建。修改源码后，开发者需安装锁定的开发依赖并重新构建。`src/index.js` 是 Host 源码，根目录 `index.js` 是发布入口；不要直接修改生成文件。构建会检查外部模块引用，并生成所捆绑依赖的许可说明。

核心测试覆盖多目录、切换主要目录、持久恢复、并发编辑、删除绑定和文件系统验证。独立加载测试会将发布入口复制到没有 `node_modules` 的临时目录，验证导入、Schema 和 Host 注册。当前工作区额外提供了从本机安装提取的真实 API 测试夹具（`.reference`，不随包分发）；存在时还验证 Host 激活、工具 Schema、会话工作目录及实际文件写入位置。尚未在运行中的 Harness UI 中完成交互验收。

右键菜单另有 React + jsdom 交互测试，验证项目行识别、忽略会话子行、键盘导航、多目录窗口、主要目录保存、标题同步、原生更多菜单、无活动聊天时的管理入口及卸载清理。
